# 3D viewer parity with KiCad's 3D Viewer

One row per behavior/setting. Status is **identical** (same constants/logic,
adapted only where the browser platform or this app's data model genuinely
requires it, noted inline), **partial** (core behavior ported, a real gap
remains, noted), or **missing** (not started, or not possible with this
app's current data model).

KiCad source snapshot: commit `8303b2ad` (see the scratchpad `kicad-src`
copy's `COMMIT` file), version 10.99.

Pure-logic ports live in `web/studio/src/kicad-port/{math3d,trackball,
camera3d,actions3d,model3d,appearance3d}.ts`, unit-tested with `npm run
test:unit` (same infrastructure as the PCB port -- see PARITY-pcb.md's own
intro). None of these files import three.js: see `math3d.ts`'s header comment
for why (the test script compiles to a scratch directory outside
`node_modules`' ancestor chain, where `require("three")` fails). The
Three.js-aware glue (reading a `kicad-port/camera3d.ts` pose into a real
`THREE.Camera`, lighting, geometry, the models of the parts) lives in
`components/viewer3d/{Viewer3D.tsx,scene.ts,modelCache.ts,partModels.ts}`; the
server's half (resolving a footprint's model path, serving it, converting STEP
to VRML) is `crates/cli/src/model3d_api.rs` and `crates/kicad/src/model3d.rs`.

`window.__eda.state().viewer3d` (`viewer3dProbe.ts`) says what the viewer draws
(models requested and loaded, parts drawn as models or boxes, scene piece counts
per name, the part under the pointer, whether the camera moves, the time to the
first real model); `web/studio/e2e/viewer3d.check.js` is the repeatable check
that drives it. Section 7 has the measurements.

## 7. Time to the first real model, before and after (2026-10-09)

**What is timed.** From the viewer asking for its first model to the first part drawn with a real KiCad model. Before this work that was the whole-board GLB of
`kicad-cli pcb export glb` (the 3D tab showed boxes until it was built and loaded); now it is the first of the board's own models. Two boards, both scratch copies:
`mcu30` (30 parts, 5 different models, 3 224 triangles) and the QA board `stonehenge` (93 parts, 16 model names of which 15 are in the installed library, 8 202
triangles; the 16th is a `${KIPRJMOD}/3D/USB4110-GF-A.STEP` of the original project that the QA copy does not carry, so J2 stays a box and the panel says why).

**How, and how far to trust it.** macOS, KiCad 10.99.0, the server a *debug* build, on a machine that other agents were compiling and testing on the whole time: the
load average was 37 to 280 during these runs, so every wall-clock figure is several times what an idle machine gives, and the figures below say their load. What does
not move much with the load is the CPU of kicad-cli (user + system, from `/usr/bin/time -p` around each run, set with `EDA_KICAD_CLI`), so it is given too. *Before* is
main at `80e972d` (its own UI and server) with a cold export: how long `GET /api/board.glb` answers "pending" -- the old UI polls it every 1.5 s and then parses 1.3 or
9 MB of GLB, so it showed its first real model later than this. *After* is this branch with a fresh server process and an empty model cache (**cold**: this machine's first
meeting with these packages) and with the cache filled (**warm**: every later session; the cache is `EDA_3DMODEL_CACHE`, by default `~/Library/Caches/eda-studio/3dmodels`).
"Server" is a client that follows the page's protocol (`GET /api/state`, `POST /api/3dmodel/prepare`, three held `GET /api/3dmodel` at a time) without a browser, timed
from the prepare to each model's answer; "page" is a headless Chrome (software GL, so slower than a real one) reading `__eda.state().viewer3d` (`requestedMs`,
`firstModelMs`, `allModelsMs`), and it opens the 3D tab at once after loading the studio, so its figures include the studio's own start-up requests that queue ahead of the
first model request.

  Body, Plated Barrels, Solder Paste, F.Mask, B.Mask, Zones, References, Adhesive, the user layers, F.Cu and B.Cu (the tracks, zone fills and pads of their layer), Through-hole and
  SMD Models (the parts of that kind, pads kept); a row hides exactly what it names.
- **Stackup colours.** `set_stackup` with F.Mask Red, F.SilkS Black, a FR4 natural dielectric and ENIG: the swatches read `#b51315`, `#0b0b0b`, `#6d744b` and `#b29c00`, the
  stackup rows turn read-only, with "Use board stackup colors" off they are the theme's and editable, and Undo takes the stackup and its colours away.
- **Animated views.** Y (front view) is a move of about a second that refuses Z while it runs (30 frames in the pane; the check does not watch it on a page that takes 250 ms
  or more per frame).
- **Screenshots** of mcu30 and the QA board were taken in the pane and in headless Chrome (not kept in the repository, which holds no images).
