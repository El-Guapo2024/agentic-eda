# 3D viewer parity with KiCad's 3D Viewer

One row per behavior/setting. Status is **identical** (same constants/logic,
adapted only where the browser platform or this app's data model genuinely
requires it, noted inline), **partial** (core behavior ported, a real gap
remains, noted), or **missing** (not started, or not possible with this
app's current data model).

KiCad source snapshot: commit `8303b2ad` (see the scratchpad `kicad-src`
copy's `COMMIT` file), version 10.99.

Pure-logic ports live in `web/studio/src/kicad-port/{math3d,trackball,
camera3d,actions3d}.ts`, unit-tested with `npm run test:unit` (same
infrastructure as the PCB port -- see PARITY-pcb.md's own intro). None of
these four files import three.js: see `math3d.ts`'s header comment for why
(the test script compiles to a scratch directory outside `node_modules`'
ancestor chain, where `require("three")` fails). The Three.js-aware glue
(reading a `kicad-port/camera3d.ts` pose into a real `THREE.Camera`,
lighting, geometry) lives in `components/viewer3d/{Viewer3D.tsx,scene.ts}`.
