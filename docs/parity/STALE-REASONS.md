# Stale reasons in `ui-parity-missing.json`

Checked on 2026-10-10 against main `89ff669` (KiCad source `8303b2ad`, 10.99). `web/studio/tools/ui-parity-missing.json` records why 187 KiCad actions are not wired (pcbnew 84, eeschema 65, common 38; `UI-ACTIONS.md`). Nearly every reason says "needs X". Since the file was written about 20 large branches have landed, so for each row X was looked for in the Rust crates and in `web/studio/src`. The three branches in flight (`task-lib-tables`, `task-sch-hierarchy`, `task-custom-pads`) were read with `git diff main...<branch>` and are not counted as existing. The audit (`web/studio/tools/ui-parity-audit.mjs`) agrees that none of the 187 is wired; it cannot know when a reason has gone stale, which is why this file exists.

| verdict | rows |
|---|---:|
| Stale: what the reason says is missing now exists | 10 |
| Partly stale: the first blocker is gone and another stays, or the reason is overstated because a path through existing code exists | 18 |
| Holds | 159 (10 of them wait for a branch in flight: library tables 6, custom pads 4) |

The work packages for the first two groups are in section 3. They are the `SR` packages here; the ranked plan that sizes them against everything else is at the end of `GAPS.md` (packages `P1` to `P21`).

## 3. Work packages for sections 1 and 2

Sized for one agent in one sitting each. Every package deletes its rows from `ui-parity-missing.json` (the audit warns about a reason for a wired action) and leaves `UI-ACTIONS.md` to be regenerated once, at merge: `node web/studio/tools/ui-parity-audit.mjs`. Nobody hand-merges that file.

**SR1. Files in** (6 stale rows: appendBoard, DdAppendBoard, ddImportFootprint, importSheet, drawSheetFromFile, ddAppendFile). Size M-L. GAPS.md package P8 (the PCB half) and P4 (the sheet half).
- One drop host: a component in `App.tsx` that hands a dropped `File`'s text to the action its extension names, as `m_acceptedExts` does in `pcb_edit_frame.cpp`, `sch_edit_frame.cpp` and the footprint editor (`.kicad_pcb`, `.kicad_sch`, `.kicad_mod`; later `.dxf`, `.svg`, library files).
- PCB: a route that reads a `.kicad_pcb` into the paste (`eda_kicad::parse_pcb_clipboard` takes a whole board) and the existing carry (`Cmd::PasteClipboard`, `kicad-port/pcbCarry.ts`).
- Schematic: `Cmd::ImportSheet` = `AddSheet` + the file's screen from `import_kicad_sch`, renumbered with `annotate_paste`, library symbols published; Draw Sheet from File and the drop are two more entry points.
- Files: `web/studio/src/actions/{commonActions,schControlActions,footprintLibraryOps}.ts`, new `components/FileDropHost.tsx`, new `crates/cli/src/append_api.rs`, new `crates/ops/src/sheet_import.rs` plus the `Cmd` hunks in `crates/ops/src/lib.rs`.
- Conflicts: `task-sch-hierarchy` (`crates/ops/src/sheets.rs`, `crates/cli/src/board.rs`, `state/store.tsx`, `actions/useActionRunner.ts`): start the sheet half after it merges; the PCB half and the drop host can start now.

**SR2. Search and inspect through the registries that exist** (1 stale row, 3 partly stale: findByProperties, InspectClearance, InspectConstraints, checkFootprint). Size M-L.
- Find by Properties: the Properties tab over `PCB_PROPERTIES`, then the Query tab with an expression evaluator over the same getters. Find itself should follow the IR that landed after it was written: user fields and hidden fields (`footprint_edits`, 2026-10-09) and zone names (`Zone.name`); `kicad-port/pcbFind.ts` still says a zone has no name and a footprint has two visible fields.
- Clearance and Constraints Resolution from `crates/drc/src/constraints.rs` (a function that returns the winner and the rules considered), shown in a report dialog. An interactive query, not a check.
- Footprint Checker: a scratch board with the one footprint through `kicad-cli pcb drc`, filtered to the footprint-level codes.
- Files: `web/studio/src/kicad-port/{pcbFind,findByProperties}.ts`, `actions/pcbFindActions.ts`, new dialogs, `crates/drc/src/constraints.rs`, new `crates/cli/src/inspect_api.rs`, `crates/kicad-engine/src/lib.rs`.
- Conflicts: none on the Rust hubs (`studio.rs` route table only); `useActionRunner.ts` and `state/store.tsx` for the dialog flags.

**SR3. Footprints that tools make, and their 3D models** (createGap and createStub stale, migrate3DModels stale, createLine partly stale). Size M.
- Microwave gap and stub: a dialog for the size, a two-pad footprint builder in `kicad-port/`, placed with `Cmd::PlaceFootprint` and its `definition`. The arc stub and the function shape need custom pads (in flight); the line needs the inductor generator.
- Migrate 3D Models: needs `FootprintEdit.models3d` (`crates/model/src/fp_edit.rs`) and its verb, the same piece the 3D model panel needs (GAPS.md package P14), so do them together.
- Conflicts: `crates/model/src/fp_edit.rs` and `crates/ops/src/fp_edit.rs` with SR4 and P14; `FootprintPropertiesDialog.tsx` with P14.

**SR4. Footprint exchange** (changeFootprint, changeFootprints, DiffFootprint, importNetlist, swapPadNets, swapGateNets partly stale; Reannotate holds until this lands). Size L. This is GAPS.md package P2 (item 26) and the order there is the order here: the per-instance footprint assignment first, then Change Footprint(s), the Footprint field of a symbol and a reference rename reaching the board, then Reannotate and Compare Footprint with Library.
- Conflicts: `crates/model/src/ir.rs`, `crates/cli/src/board.rs` and `crates/ops/src/lib.rs` with every package that adds an overlay; `crates/ops/src/lib.rs::rename_symbol` and `annotate` with `task-sch-hierarchy`.

**SR5. Schematic design blocks** (7 partly stale rows, 16 that hold). Size L. GAPS.md package P18. After library tables (P3: the block library is a table) and SR1 (placing a block is Import Sheet in KiCad: `SCH_DRAWING_TOOLS::ImportSheet` runs for `placeDesignBlock` too).

**SR6. Specctra** (exportSpecctraDSN partly stale; importSpecctraSession holds). Size S-M. GAPS.md package P19: expose `to_dsn` as a download, then write the SES reader; `pcbnew/specctra_import_export/specctra_export.cpp` and `specctra_import.cpp` are the references.
