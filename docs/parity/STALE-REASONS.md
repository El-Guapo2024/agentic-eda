# Stale reasons in `ui-parity-missing.json`

Checked on 2026-10-10 against main `89ff669` (KiCad source `8303b2ad`, 10.99). `web/studio/tools/ui-parity-missing.json` records why 153 KiCad actions are not wired (pcbnew 61, eeschema 59, common 33; `UI-ACTIONS.md`; 187 when this was checked, until `task-lib-tables` wired five library-table rows, `task-fp-assign` four footprint rows (Change Footprint, Change Footprints, Compare Footprint with Library and Geographical Reannotate), `task-sch-details` the two pin-swap rows, `task-fp-3d` Migrate 3D Models and `task-search-inspect` four (Find by Properties, Clearance Resolution, Constraints Resolution and the Footprint Checker), `task-length-tuning` the nine generator rows, `task-import-foreign` the two import rows, Import Non-KiCad Board File and Import Non-KiCad Schematic File, and `task-design-blocks` 22 design-block rows). Nearly every reason says "needs X". Since the file was written about 20 large branches have landed, so for each row X was looked for in the Rust crates and in `web/studio/src`. The three branches in flight then (`task-lib-tables`, `task-sch-hierarchy`, `task-custom-pads`) were read with `git diff main...<branch>` and are not counted as existing. The audit (`web/studio/tools/ui-parity-audit.mjs`) agrees that none of the 153 is wired; it cannot know when a reason has gone stale, which is why this file exists.

| verdict | rows |
|---|---:|
| Stale: what the reason says is missing now exists | 8 |
| Partly stale: the first blocker is gone and another stays, or the reason is overstated because a path through existing code exists | 12 |
| Holds | 151 (4 of them wait for a branch in flight: custom pads 4) |

The work packages for the first two groups are in section 3. They are the `SR` packages here; the ranked plan that sizes them against everything else is at the end of `GAPS.md` (packages `P1` to `P21`).
