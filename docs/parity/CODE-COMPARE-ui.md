# UI action handlers vs. KiCad source -- code-level comparison

Scope: every action registered with `m.set("...")` in `web/studio/src/actions/useActionRunner.ts` (266 distinct action names, including the 30 `layerInnerN` ones generated in one block; `AttemptFinish`, `UndoLastSegment`, `trackWidthInc/Dec` are registered twice and counted once). KiCad source: master @8303b2ad (`/home/user/kicad-src`). Method: for each handler the cited KiCad function was opened and read, then compared for what it does, preconditions (selection / tool state), what it changes, edge cases (empty selection, locked items, multi-select, cancel) and messages. Read-only analysis: no code was changed.

Status key: **FAITHFUL** same behaviour; **ADAPTED** deliberately different because the model differs (design.json always saved, one layer pair, one symbol library, no project files...); **DIVERGENT** claims to port but a KiCad user would notice; **UNVERIFIABLE** cited source not found / handler too thin to judge. Dialog-opener rows (`Opener only`) judge the wiring of the action, not the dialog's contents.

Counts are per registered action (a row covering N actions adds N). By block: pcbnew parity block and eeschema/common parity blocks are sections 1-3; older handlers are sections 4-5.

Cross-cutting findings that explain many rows:

1. **(FIXED for R/F/M/Del/E/Shift+M/Ctrl+X and the schematic R/X/Y/M/G/E/U/V/F; remaining: Ctrl+T, SelectConnection, copyAsText.) No `RequestSelection` hover fallback in the older handlers.** KiCad's R, F, M, Del, E, U, Ctrl+T, Shift+M, Ctrl+Shift+C all act on the item under the cursor when nothing is selected. Only the new pcbnew parity block has `requestSelection()` (useActionRunner.ts:1502); rotate/flip/move/delete/properties/SelectConnection/moveExact/createArray/copyAsText and every schematic edit still read `state.selection` only.
2. **(FIXED for rotate/flip/move drop/align/distribute/delete/cut/track-width via `Cmd::Batch`; remaining: position-relative dialog.) One backend Cmd per item = one undo step per item.** Each successful `/api/cmd` pushes one snapshot (crates/cli/src/board.rs:349). KiCad commits a whole multi-item operation once. Affected: multi-item move drop (`commitMove`), PCB/schematic align and distribute, multi-footprint flip (2 per part), multi-item delete (copper is batched in `deleteFull` only), position-relative.
3. **(FIXED: zoom family, fit, select all work on the Schematic tab; Ctrl+Z is editor-scoped. Copy/cut/paste/Space remain PCB-only.) Tab gating by name prefix** (`actionTabGate.ts`): `common.*` actions are enabled on every tab, but many handlers are `pcbOnly`, so on the Schematic tab the View/Edit menu entries are enabled yet do nothing (zoom family, fit, select all, copy/cut/paste, Space). On the Footprint/Symbol editor tabs `common.Interactive.undo/redo` reach the PCB undo stack.
4. **Schematic selection is symbols + wires only** (SchematicView.tsx hitSymbol/hitWire). Labels, power symbols, no-connects, text and bus entries cannot be selected, hence cannot be deleted, rotated, copied-as-text or aligned, although `Cmd::DeleteLabel/DeleteSchText/DeleteNoConnect/DeletePowerSymbol/DeleteBusEntry` exist and nothing in the UI sends them.

## Divergences to fix

Ordered by how often a user is likely to hit them (most frequent first). Line numbers are in `web/studio/src/actions/useActionRunner.ts` unless stated.

1. **Hover + hotkey does nothing (R, F, M, Del, E, U, Shift+M, Ctrl+T, Ctrl+Shift+C; schematic R/X/Y/M/E/Del).** Scenario: hover a footprint, press `R` -> KiCad rotates it; ours does nothing because `rotateSelection`/`flipSelection` filter `state.selection` (store.tsx:1572-1593) and `common.Interactive.delete` (167) iterates `state.selection` only. Fix: reuse `requestSelection()` (1502-1508) in the older PCB handlers (rotate, flip, move 637, delete 167, properties 668, SelectConnection 512, moveExact 467, createArray 345, copyAsText 1418) and add a schematic equivalent using `hitSymbol`/`hitWire` (SchematicView.tsx:89,103) for 927-956, 901-925, 967-971. Clear the temporary selection afterwards when it came from hover (`selection.IsHover()` in source).
2. **Multi-select ignored by schematic Rotate/Mirror, and PCB Rotate/Flip skip non-footprints.** Scenario: box-select three symbols and press `R`/`X` -> only `[...state.selection][0]` changes (927-956). On the PCB, `R` on a selected track/via/shape/text does nothing (store.tsx:1573 `partByRef(r)?.placed`). Fix: loop over every selected symbol with one shared pivot (sch_edit_tool.cpp:969 principalItemCount>1 branch) and extend `rotateSelection`/`flipSelection` to the kinds that have move Cmds (`move_exact` already takes a pivot).
3. **Ctrl+Z / Ctrl+Y on the Footprint Editor or Symbol Editor tab undoes the PCB.** `common.Interactive.undo` (438) -> `api.undo()` (store.tsx:1730) posts `"pcb"` for every tab except schematic. Fix: in the registry dispatch to `useSymApi().undo/redo` and the footprint store's `undo/redo` by `state.tab` (both exist: symbolEditorStore.tsx:265, footprintEditorStore.tsx:269) or disable the action on those tabs in `isActionEnabledForTab`.
4. **Zoom/fit/centre/F1/F2/Home are dead on the Schematic tab.** `common.Control.zoomFitScreen/FitObjects/zoomIn/zoomOut/zoomInCenter/zoomOutCenter/zoomCenter` are wrapped in `pcbOnly` (556-613) but listed in sch_menus.json and enabled by the `common.*` gate. Scenario: schematic tab, View > Zoom to Fit or `F1` -> nothing. Fix: use the `activeView()/setActiveView()` helpers already defined at 1250-1251 (and the schematic bounds) instead of `pcbOnly`/`state.view`; same for `selectAll`/`unselectAll`/`cut`/`copy`/`paste`/`resetLocalCoords`.
5. **Multi-item operations are N undo steps, and delete/cut have wrong scope.** Scenario: select 4 footprints, drag-move, Ctrl+Z reverts only one; select 5 tracks, Del, Ctrl+Z restores one; Ctrl+X on a footprint unplaces it with nothing copied (159-165, store.tsx commitMove/alignSelection/distributeSelection). Fix: add a batch Cmd (or a `Cmd::Batch { cmds }` snapshot-once wrapper in crates/ops) and use it in commitMove, align/distribute, delete (also skip locked and delete groups), and make `cut` copy only what it deletes (or refuse footprints/dimensions).
6. **Select All ignores selection filters and layer visibility.** Scenario: hide `B.Cu`, turn the Tracks filter off, `Ctrl+A`, `Del` -> hidden-layer tracks are selected and deleted. Fix at 873-888: apply `state.selectionFilter` (tracks/vias/zones/graphics/text/dimensions keys exist, selectionCandidates.ts:48) and `layerVisible`, include dimensions.
7. **W / Shift+W / `\` (track width and via size) differ from BOARD_EDITOR_CONTROL.** Scenario: select a 300 um track, press `W`: ours sets it to `presets[1]` (possibly smaller) via the global index and clamps at the list end; source sets it to the next larger preset above its own width and, with the width cycle, WRAPS to the first. While routing, `W` does not change the live route because the route-specific handler at 250-251 is overwritten by 800-801. Fix: implement the per-item rule for track/via-only selections (board_editor_control.cpp:1034-1047, ViaSizeInc :1182-1236), wrap in `cycleTrackWidth`/`cycleViaPreset` (board_editor_control.cpp:1085-1087, :1226-1236), and keep the routing branch distinct (register the cycle at 800 only when not routing).
8. **Grid next/prev (`N`) clamps instead of wrapping and gives no feedback.** `cycleGrid` (851-855) clamps; source wraps (common_tools.cpp:495-518), snaps the cursor to the new grid and pops the grid feedback. Fix: modulo wrap and reuse `applyGridPreset`'s cursor snap + toast (1347-1356).
9. **Schematic Align and Align-to-Grid break connectivity.** Scenario: align left two symbols whose pins were wired -> symbols move by arbitrary micrometre deltas (no `adjustDeltaForGrid`), pins leave the 50 mil grid and wires no longer connect; Align to Grid moves symbols without dragging attached wires (1197-1231). Fix: snap each delta to the connection grid, move wire endpoints with `drag_symbol` (`computeDragAttachment`), include wires/labels, add the locked/cursor target rule, batch into one undo step.
10. **PCB Align/Distribute ignore locks and the cursor target; Position Relative ignores locks and silently skips tracks.** Fix: skip locked ids, use `lockedSet`/cursor box for `selectTarget` (align_distribute_tool.cpp:104-133), batch the commit.
